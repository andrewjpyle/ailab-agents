# Model card: bounded tool-using agent (stub brain and recorded model)

A model card for the agent that ships with this lab. Labs built from it should copy this
structure for every agent and tool set they gate on.

## Pipeline details

| Field | Value |
|---|---|
| Agent | Bounded ReAct loop (`max_steps` 6), action grammar `ACTION: <tool> <arg>` or `ANSWER: <text>` |
| Tools | `retrieve` (deterministic token-overlap lookup) and `calc` (arithmetic over an AST whitelist, never `eval`) |
| Default brain | `StubProvider` (model id `stub-agent-v1`): format-valid, task-naive, offline |
| Live brain | `OllamaProvider` records a cassette; `ReplayProvider` replays it offline |
| MCP | Stdlib JSON-RPC 2.0 over stdio (`initialize`, `tools/list`, `tools/call`) over the same registry |
| Version | v1 (package 0.1.0) |
| Owner | Andrew Pyle |
| License | Apache-2.0 |
| Inputs | A natural-language question and a corpus of factual records |
| Outputs | A trajectory of tool calls and observations, then a final answer |

## Intended use

- Primary: a reference agent that demonstrates necessary tool use, a bounded loop, an MCP parity
  contract, and a gate that layers authenticity and non-triviality checks on numeric floors.
- Users: engineers learning agent evaluation, or building a lab from this template.
- Out of scope: answering real user questions, any decision affecting a person, any corpus other
  than the synthetic station corpus, and any claim that the stub brain reasons.

## Data

- Corpus: `fixtures/corpus.jsonl`, 16 synthetic "research station" records with numeric facts.
  Provenance and sha256 in [FIXTURES.md](FIXTURES.md).
- Tasks: `fixtures/tasks.jsonl`, 20 tasks (15 multi-hop retrieve-then-calc, 5 single-hop
  retrieve-only) with normalized ground-truth answers.
- No real product, support, or personal data; the stations are invented.

## Metrics

| Metric | Why |
|---|---|
| task_success | Did the agent's final answer match the gold answer (normalized)? The primary metric |
| tool_precision | Of the agent's tool calls, how many were among the task's required tools |
| invalid_action_rate | Fraction of steps that parsed as neither a tool call nor an answer |
| mean_steps | Mean trajectory length, to expose a degenerate loop |
| authenticity | Is the provider the recorded real model? A stub cannot pass |
| tool_usage | Did the run call any tool at all? |
| non_triviality | Are the per-task answers distinct, or byte-identical (no task effect)? |

Gate (in `eval_config.toml`): task_success >= 0.60, tool_precision >= 0.50, both with a 0.05
tolerance band, invalid_action_rate <= 0.20, plus the authenticity, tool-usage and non-triviality
checks. Exit 0 pass, 1 regression, 2 bad config or data (empty tasks, or fewer than `min_tasks`).

## Results

### Stub baseline (the task-naive floor, `results/stub_baseline.json`)

| Metric | Score |
|---|---|
| task_success | 0.0000 |
| tool_precision | 1.0000 |
| invalid_action_rate | 0.0000 |
| mean_steps | 2.0000 |
| n | 20 |

The stub retrieves once and answers with the raw retrieved text, so it uses the right tool
(`tool_precision` 1.0) and never gets the number (`task_success` 0.0). It fails the gate on
`task_success` and on authenticity, by design. These numbers are generated by `ailab-eval` and
validated against `docs/LEARNING.md` by `make check-learning-numbers`.

### Real brain (gemma3:27b, recorded separately)

Not committed in v1. The real pass is produced by `make record` against a local Ollama server
(host from `OLLAMA_HOST`, never stored), which drives the SAME bounded loop and writes
`fixtures/cassettes/agent_gemma3_27b.json`. `ailab-eval --provider replay` then scores the agent
against it offline, and the CI `eval` job replays it. Until that cassette exists the eval job is
expected to fail: the committed cassette is a stub, and a stub cannot pass the gate.

## Limitations

- The stub brain is a FORMAT path. Its metrics describe the loop machinery, not reasoning.
- `task_success` is an exact normalized match. It does not credit a correct method with a wrong
  final number, nor a correct number reached without the required tools (tool_precision catches
  the latter).
- A 20-task set exercises the gate. It is not large enough to compare close agents.
- The corpus is synthetic; the numbers describe this lab, not any real agent.

## Ethical considerations

- The data is synthetic and contains no personal information, so no consent issue arises.
- A real agent that calls tools can take actions with side effects. This lab's tools are
  read-only (a lookup and a pure calculation), and the calc tool uses an AST whitelist so an
  expression can never execute arbitrary code.
- Before trusting an agent on real tasks, evaluate it on representative, consented, appropriately
  licensed data, and sandbox any tool that can act on the world.

## Caveats and recommendations

Treat the stub as a floor and a demonstration. Earn the green gate with a real recorded model,
keep the authenticity and non-triviality checks in every table, and never commit a stub recording
labelled as the real model.
